# 规划 3D 资产生成路线

**路线是决策，不是顺序。** 同一条链路有直连和三视图两条路，选错不会报错，只会白花钱——而白花的钱通常花在第 4 步建模上，因为在花钱之前没人拦你。

## 何时使用

- 用户说想做 3D 资产 / 模型 / 网格 / 道具 / 角色，但没定路线
- 用户同时提到 3D 和动画、视频、场景（**必须先问清楚顺序**）
- 拿到一张图问「这个能不能变成模型」
- 一批同系列资产的批量生产

不用：只要代码化精确模型（支架、外壳、卡扣、齿轮）→ **REQUIRED SUB-SKILL:** 用 `3d-model`（OpenSCAD 参数化）。有机形体（角色、生物、布料、雕塑）才走本 skill。

## 核心：先定「后面要不要动起来」

这是**成本差一个数量级**的问题，必须在路线之前问清。

| 用户意图 | 后果 |
|---|---|
| 只想看 / 打印 / 静态展示 | 不需要三视图一致性投入 |
| 要做游戏/引擎资产 | 尺寸、LOD、贴图规格要一开始就锁 |
| **最终为了视频/动画** | **决定要不要做 3D**，见下方硬约束 |

## 硬约束：跳 image-to-video 就别做 3D

**如果最终交付物是一段视频，且不要求精确可控的镜头运动，那整条 3D 链路是浪费。** 概念图直接进视频生成即可。

唯一例外是混合路线（3D 渲染出多视角图再转视频），此时 3D 的作用是**锁住身份一致性**，不是为了得到几何。

细节与三条路径对比 → **REQUIRED SUB-SKILL:** 用 `animating-3d-assets`。

## 路线判据

| 情况 | 路线 |
|---|---|
| 规则几何体、机械件、简单道具 | 直连，甚至不该用 AI |
| 角色 / 生物 / 有机曲面 | 三视图 |
| 需要指定朝向、姿态、构图 | 三视图 |
| 同系列批量、多个资产要像一家人 | 三视图（一致性收益最大） |
| 一次性的粗糙原型 | 直连 |

判据是**需求**，不是「图好不好看」。图好看与否由生图阶段负责，与路线无关。

## 红线：已有 IP 或已有参考图的角色，不许静默降级到文生图

判据：请求里出现任一即为「有身份约束」——具体作品名／角色名、用户手上有参考图，
或要求「和某个角色一样」。

**有身份约束时默认走参考图路线。参考图路线走不通时，停下来告诉主人
「参考图没走通，文生图不能保证还原度，要不要接受偏差」，得到答复再继续。
不许自己滑到文生图。**

参考图为什么常走不通：`skills/3d-asset-pipeline/SKILL.md` 的「参考图的坑」记着，
`subject_reference` 只收公网 URL，本地图必须先上图床，否则
`status_code=1000 disallowed image url`。这条路径一失败就往文生图掉，掉的瞬间无任何告警。

实测踩过的坑：把《绝区零》星波雅比的 `identity_anchor` 写得完全正确
（黑发带青蓝渐变、紫瞳、黑白蓝军装），但只存在 manifest 里、没进 prompt 正文，
出图成了**金发红瞳、黑白红配色**，三视图 / 网格 / 视频首帧全错，
而 negative prompt 里明明写了 `not blonde`。根因是提示词里混进了
「保持参考图上角色…不变」这种空指令（模型手里根本没有参考图），占掉权重位，
identity_anchor 反而没进去。

**降级到文生图时的硬性要求**：`identity_anchor` 每一条特征逐字进 prompt 正文，
并删掉所有「保持参考图…」「与参考图一致」类空指令。
特征只存在 JSON 元数据里等于没锁身份。

## 真实世界尺度（现在就说，不要等到最后）

**1 单位 = 1 米。** AI 生成的网格尺寸经常离谱，而且**不会报错**——模型能加载、能渲染，只是放到场景里小得像粒沙或大得像山。

在路线确定时就把目标尺寸写下来（人 1.7、门 2.0、桌子 0.75），它要一路传到导出。

- 走三视图 → **REQUIRED SUB-SKILL:** `authoring-three-view-references`
- 走直连或三视图之后 → **REQUIRED SUB-SKILL:** `finalizing-3d-assets`

## 常见错误

**1. 把三视图当成必经步骤。**
不是。三视图是**质量分支**：直连快而粗，三视图慢但可控。简单道具走三视图是纯浪费。

**2. 先想「怎么生成」，再想「用来干什么」。**
顺序反了。用途决定路线，路线决定生图，生图决定提示词。

**3. 假设「生成出来就是资产」。**
建模只占这项工作的很小一部分，**没有 UV、没有规范贴图、没有尺寸对齐的网格不是资产，是草稿**。

**4. 参考图一失败就默默转文生图。**
IP 角色转文生图 = 身份漂移重灾区（金发替黑发、红瞳替紫瞳，且全链路跟着错）。
先问主人再降级，见「红线」一节。

**5. 引用不存在的子 skill 名。**
本文件早期写的是 `authoring-three-view-assets`，磁盘上实际叫
`authoring-three-view-references`——写交接段时凭印象起名，下游按名查找直接断链。
改这类文件时用 `ls skills/ | grep <关键词>` 核对真实目录名。
