# 让 3D 资产动起来

**先定动态类型，再决定要不要 3D。** 顺序反了，整条 3D 链路可能白做——这是整条链路上最贵的冤枉钱。

## 硬约束：走 image-to-video 就别做 3D

如果交付物只是一段视频，且**不要求精确可控的镜头运动**，那概念图直接进视频生成即可，前面所有三视图和建模都是浪费。

## 三条路径

| 路径 | 做法 | 拿到什么 | 代价 |
| --- | --- | --- | --- |
| **A 渲染成片** | 3D 场景 → 逐帧渲染 → 编码 | 身份完全一致、镜头精确可控、可多机位、能复用资产 | 逐帧渲染耗时；需 Blender（**本机未装**）；动画需先绑定 |
| **B 图生视频** | 概念图 / 三视图 → image-to-video | 快、便宜、镜头语言自然 | **mesh 到这步白做了**；身份会漂；无法精确指定动作 |
| **C 混合** | 3D → 渲多视角图 → image-to-video | 保留身份，**不需绑骨** | 控制力弱于 A；3D 的作用是锁身份而非给几何 |

## 选哪条

| 情况 | 走哪条 |
| --- | --- |
| 镜头运动要精确、要多机位、要复用同一资产 | A |
| 快速出片、镜头语言自然即可、只要一条短视频 | B |
| 角色没有绑定骨骼，但必须保持长相 | C |
| 要精确的动作（行走、攻击、拿取） | A，**必须绑骨** |
| 只要一个展示性的环绕/推拉镜头 | C，或 A 的单帧序列 |

## 落到本机

`video-edit` skill 底层是 ffmpeg，能吃图片序列与视频，已支持切片、拼接、变速、竖屏裁切、烧字幕、水印。**生成本 skill 的产物喂给它，是"素材被使用"的落地方式**——把图片序列按帧率编成 mp4 就完成了最简版路径 A。

已知：视频下载与剪辑链路（`video-downloader` / `video-edit` / `video-summary`）都只吃**已有素材**，不产素材——本 skill 与它们是上下游关系。

## 一致性陷阱

**每一步都在漂移。** 图 → 三视图会漂，三视图 → mesh 会漂，mesh → 视频会漂。

唯一对策：**中间产物不重新生成，把参考逐级传下去。**

- 三视图定稿后，建模只以它为准，不再回看原概念图
- 走路径 C 时，渲染用的参考视角与视频生成用的首帧必须是**同一张**
- 每一级都记下 seed / 模型 / 参数，复现失败时只改一处

## 验收门

- [ ] 目标视频时长、帧率、分辨率、编码格式已确定
- [ ] 走 A：场景已绑定或已确认无需绑定；单帧测试渲染通过
- [ ] 走 C：多视角图数量足够覆盖镜头运动范围
- [ ] 人物在首帧与尾帧的服装、发型、配饰一致
- [ ] 输出文件已在本地播放验证，不是只看生成成功提示

## 常见错误

**1. 先建 3D 再想要视频。** 应该先问"要不要动起来"。

**2. 走 B 却期待身份严格一致。** image-to-video 会重绘特征，服装纹样、配饰数量都可能变。

**3. 没绑骨就想做精确动作。** 路径 B/C 只能做镜头运动，做不了"角色抬手"。精确动作必须绑骨走 A。

**4. 中间产物重新生成。** 每次重新生成都是一次漂移，参考链一断，前面全废。

**5. 只看"生成成功"就交付。** 必须本地播放验证，尤其检查首尾帧一致性。

**6. 忘了垂直屏。** 手机端交付是 9:16，横屏片直接裁切会毁构图。
