# 前端点击测试协议

## 目标

验证“用户真的点了会发生什么”，而不是只验证组件能编译。优先使用真实浏览器和可访问性树/Playwright，必要时截图。

## 每次点击必须记录

```text
页面 URL：
起始状态：
点击目标：
预期变化：
实际变化：
Console：
证据：
```

## 最低场景

### A. 入口跳转

1. 打开主页面。
2. 点击目标入口。
3. 等待路由或面板状态更新。
4. 验证 URL/hash、标题、面板或可见内容变化。
5. 如果是 `/voice`，验证能返回主界面且返回按钮不与顶部栏重叠。

### B. 设置弹窗

1. 打开设置。
2. 点击左侧每个分类。
3. 修改至少一个开关或选择项。
4. 关闭并重新打开，确认值仍在。
5. 刷新页面后再次确认持久化。
6. 检查弹窗没有被返回按钮、会话栏或其他浮层遮挡。

### C. 主题

1. 打开设置外观页。
2. 点击 `基础`，读取弹窗实际背景、文字色和强调色。
3. 点击 `ZZZ`，读取实际背景、文字色和强调色。
4. 确认选项只有 `基础` 和 `ZZZ`。
5. 切回原主题，确认状态可逆。

### D. 菜单、开关和表单

1. 点击菜单展开，验证子项可见且可点击。
2. 点击开关，验证视觉状态和实际业务状态同时改变。
3. 点击提交按钮，验证 loading、成功/失败提示和持久化。
4. 关闭菜单前先处理遮挡层；不要让隐藏元素被误认为已点击。

## 失败判定

出现以下任一项即不算通过：

- 点击后 URL、DOM、面板、开关或内容没有变化。
- 首次点击没有反应，需要重复点击才生效。
- 状态只在内存里变化，刷新后丢失。
- 主界面和 `/voice` 显示不一致。
- 出现新的 console error。
- 元素被遮挡、溢出、错位或无法在窗口变小后操作。
- 只提供“构建通过”或“代码看起来正确”作为证据。

## 证据要求

至少提供一项可复核证据：

- 页面 URL + 可访问性树中的状态变化。
- 元素属性/文本/计算样式的前后值。
- 截图或录制片段。
- 接口响应与页面显示同时变化。
