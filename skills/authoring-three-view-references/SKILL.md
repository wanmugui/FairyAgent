# 生成三视图参考

## 硬边界：没有图像模型能给出几何正确的三视图

2026-10 核实四家主流服务，结论一致：

| 服务 | 多视图模式 | 可控角度的手段 |
| --- | --- | --- |
| FLUX.2 | 无。官方工具目录只有 Outpainting / Eraser / Deblur / Virtual Try-On / Video Edit / Upscale | 提示词 + 最多 8 张参考图 |
| Seedream 系列 | 无。「组图」官方定义是**内容关联**的变体，不是指定角度 | 提示词 + 参考图 |
| Qwen-Image | 无多视图参数 | 提示词 + 参考图 |
| SeedEdit v3 | 无。专攻身份保持 | 图生图，锁服装容貌发型 |

**能控角度的只有提示词。** 扩散模型在潜空间重建外观，不保证正交投影下的几何闭合。**三视图是需要迭代逼近的参考，不是精确图纸**——把它当图纸用，3D 阶段必然翻车。

## 路线选择：默认本机，云端按需手动开

**默认走本机路线，不烧额度。** 云端 Tripo 已降级为手动开关，需要时显式开启。

### 默认：本机路线

1. `image_generate` 一次出三视图（见下方「关键手法：一次出图，再裁切」）
2. 建模走本机 TripoSR（`generating-3d-models` 的本地路径，CPU 约 27 s/个，免费离线）

出图侧**支持参考图**——`threeview.py --ref-url <公网URL>` 会带上 MiniMax
`subject_reference`（`type=character`，`fidelity=0.8`）锁住角色：

```bash
python3 threeview.py --desc "..." -o out/char --ref-url https://<图床>/ref.png
```

**唯一限制是 `subject_reference` 只收公网 URL**：裸 base64 和 `data:image/...;base64,`
都会被 SSRF 校验拒掉，报 `status_code=1000 disallowed image url`（和图片体积无关）。
所以本地图要先上图床；没有图床时才退到纯文生图。

⚠️ 常见误判：`image_generate` **工具**确实不吃参考图（`image_paths` 明确不支持），
但那是**工具 schema 的限制，不是 MiniMax 出图能力的限制**。
别因为工具不支持就以为整条链路只能文生图——脚本路径是通的。

代价要说清楚：本机 TripoSR **只吃单图**，三视图要自己挑一张喂。

### 手动开关：云端 Tripo

**默认关闭。** 只有主人明确要求"用云端 / 出精修件 / 不在乎额度"时才开。

```bash
TRIPO_CLOUD=1 tripo generate image-to-multiview concept.png -o <输出目录> --json --no-open
```

它基于几何理解生成视图，**背面不是靠提示词脑补**，然后 `multiview-to-model`
直接吃这套视图形成闭环——这是云端唯一真正不可替代的价值，别的都别夸大。

凭证保留不删：`~/.tripo/config.json`、`~/.tripo_key_cn`、`~/.tripo_key_ov`。
CLI 在 `~/.local/bin/tripo`。要切回来只需带上 `TRIPO_CLOUD=1`。

→ **REQUIRED SUB-SKILL:** 建模用 `generating-3d-models`

### 关键手法：一次出图，再裁切

`image_generate` **工具**走 MiniMax `image-01`，`image_paths` 明确不支持，所以工具层只能文生图。
但 `scripts/threeview.py --ref-url` 用的是 MiniMax `subject_reference`，**参考图能力是有的**。

**有公网参考图时优先用 `--ref-url` 锁角色**；只有拿不到公网 URL 时，
才退到"一次出图再裁切"这套纯文生图打法。

### 关键手法：一次出图，再裁切

**既然不能喂参考图，那就让三个视图在同一次生成里产生——身份天然一致。**

```
一次调用 → sheet 图（面像 + 全身正面 + 全身背面 并列）
              ↓ 裁切
        3 张分离单视图 → 喂 3D 服务
```

这样同时拿到双产物，且**绕开了"三次调用三次漂移"这个最大的一致性漏洞**。这是无参考图能力时唯一能保证身份一致的做法。

代价（必须如实告知用户）：

- 裁切后各视图的**光照与比例可能有细微差异**（同一次生成，但不同区域渲染独立）
- 背面容易糊——它是模型最不熟悉的视角
- 拼接缝可能切到肢体，给裁切留 5% 余量

**分离视图不可得时**（裁出来明显不能用），退到下一步的兜底方案。

## 提示词构造

先锁身份，再锁排布，顺序不能反：

> 保持参考图上的角色服装、容貌、发型不变。
> 左侧：参考图上角色的面部近景，简单灰色背景。
> 右侧：同一位角色的全身正面照与全身背面照并列展示，形成标准人物造型三视图效果。

无参考图时删掉"保持参考图上…不变"这句（模型没看到参考图，这句是空指令），改为**在同一条 prompt 里把身份特征写死**：

> 同一名角色的三视图设定图。角色为 20 岁男性，黑色短发，左耳银质耳钉，
> 身穿深蓝色连帽卫衣与灰色工装裤，黑色作战靴。
> 左侧：面部近景，纯浅灰背景。
> 右侧：全身正面立姿与全身背面立姿并列，双臂自然下垂，浅灰背景，纯色，无道具。

**三处必须逐字固定**：角色年龄性别、发型与标志配饰、服装全套。改一个字都会重掷身份。

## 双产物

| 产物 | 给谁 | 形态 |
| --- | --- | --- |
| **评审稿** | 人看，确认造型后再花 3D 的钱 | 拼版 sheet |
| **建模输入** | 3D 生成服务 | **分离单视图**，正/侧/背各一张，单主体居中 |

**把拼版 sheet 整张喂给 3D 服务，模型容易读成三个不同的物体。** 多数多视图 3D 服务期望独立单图。死在这里的典型表现：三视图做得漂漂亮亮，出来的模型一塌糊涂。

## 验收门

- [ ] 三个视图的服装、发型、配饰**逐件一致**（不是"看起来像"）
- [ ] 角色为 T-pose 或 A-pose，双臂张开不遮挡躯干
- [ ] 裁切后单主体、居中、背景干净、尺寸一致
- [ ] 已同时产出评审稿与建模输入两份

任何一条不过，**不要进入 3D 阶段**——每多迭代一轮比直接重来便宜。

## 兜底：几何正确只能从 3D 渲

若裁出的视图仍不可用，改走**图 → 3D → 渲正侧背**。视图几何天然正确，代价是每步更贵（火山方舟 `doubao-seed3d-2.0` 约 ¥2.40/次）。

## 常见错误

**1. 分三次调用分别出正/侧/背。** 无参考图时这是错的——三次调用等于三个身份。必须一次出图再裁切。

**2. 每次迭代重写 prompt。** 重写等于换了个任务。身份描述块逐字复用，只改排布措辞。

**3. 只出拼版 sheet 就去建模。** 见「双产物」。

**4. 忽略背面。** 背面最容易糊，而它正是三视图存在的意义。糊了就在 prompt 里加背面细节描述再重出。

**5. 拿三视图当精确图纸。** 它是外观参考，厚度、连接、内部结构建模阶段不会给你。
