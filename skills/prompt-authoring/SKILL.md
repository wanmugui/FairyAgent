# Prompt 扩写与优化

把用户的**一句话意图**补全成外部工具能直接吃的完整 prompt。工具不会替你扩写——`image_generate` 的契约写明 "this tool does not invent, translate, or enrich it"，所以这一步必须显式做。

## 何时用

- 用户描述了一个想法，但没说清风格、比例、细节 → 需要扩写后再投喂工具
- 用户自己写不出那段长 prompt（这是最常见的情况，不是缺陷）
- 给定时任务/子任务写自用指令，需要保证对方能独立执行

**不适用**：改代码、查资料、纯聊天。用户已经给了完整 prompt 时不要擅自重写。

## 核心：六段骨架

好 prompt 的骨架是固定的，缺哪段就补哪段。按此顺序写，覆盖式补全而非重写。

| 段 | 作用 | 缺失的后果 |
|---|---|---|
| **主体** | 画面/产物里到底有什么 | 模型自由发挥，跑偏 |
| **视角与构图** | 从哪看、占多大、什么朝向 | 视角错误要重渲 |
| **风格** | 渲染/画法/介质 | 风格随机，每次不一致 |
| **材质与细节层次** | 表面表现、精度档位 | 出概念图不出成品 |
| **对比与光效** | 冷暖、明暗、焦点引导 | 画面平，没记忆点 |
| **硬约束** | 尺寸、格式、禁止项 | 尺寸错、元素漏 |
| **负面清单** | 明确不要什么 | 脏元素、穿模、糊脸 |

**关键：负面清单是最被低估的一段。** 用户写不出它，通常不是因为不会写，而是没人告诉他要写。

## 怎么判断缺哪段

对照骨架逐条问，只补缺的，**不要把已经说清的重写一遍**。用户已经说「三渲二、浓厚日式二次元氛围」，就别再解释什么叫三渲二。

判断信号：

- 只说「做个 X」→ 缺视角、风格、约束、负面清单（4 段全缺）
- 说了主体和风格 → 通常缺视角、负面清单
- 说了视角没说什么都不见 → 可能缺风格
- 产物跑偏了 → 优先查负面清单和硬约束，而不是加更多形容词

## 元素穷举：清单要落数量

用户写不出细节时，用**穷举法**给候选清单，让用户勾选或全收。

规则：
- 同类元素列全，宁多勿漏（用户删比你想容易）
- 能给数量的给数量（「5 处积水」比「一些积水」有效）
- 要素覆盖：主体建筑 / 附属设施 / 地面 / 天空环境 / 人物（常被忘）/ 光源

参考量级：微缩场景 20-40 个元素是合理密度。

## 风格描述：给可判定的词

写风格要写**能对照检验的**特征，不写感受。

- ❌「好看的」「高级的」「精致的」
- ✅「硬边分层、球面三级色阶、黑描边、自发光不过色调映射」
- ✅「干净、轮廓明确、色彩柔和但有夜景霓虹层次」

后者能被验收，前者不能。

## 反面：不要把 prompt 写成需求文档

- ❌ 罗列「用户需求、验收标准、边界条件」小标题
- ❌ 写「请确保……」「不得……应该……」这种公文腔
- ✅ 直接写成一段或几段可直接投喂的连续描述

prompt 是给**生成方**看的，不是给人审批的。

## 自检清单

投喂前逐条确认：

- [ ] 六段骨架齐了（至少主体、视角、风格、硬约束、负面清单）
- [ ] 没有重复用户已说清的内容
- [ ] 风格描述可验收，不是形容词堆砌
- [ ] 有负面清单，且具体（不是「不要 ugly」）
- [ ] 尺寸/数量/格式等硬指标是明确数字
- [ ] 是可直接用的成品，不是思路说明

## 示例：一句需求 → 完整 prompt

**用户说**：「做一个雨夜便利店街角小场景」

按骨架补全（视角、风格、材质、对比、约束、负面清单）后：

> 制作一个雨夜便利店街角小场景，以第三视角观察整个场景，整体像一个可以自由拖拽、旋转、缩放观看的微缩三维模型 / 小型景观，没有任何 UI 界面元素。地面为一个完整的正方形底座，所有元素都搭建在这个底座上，构图紧凑、层次清晰，整体呈现出小巧、精致、可收藏的模型感。画面风格为三渲二，强调浓厚的日式二次元动画氛围，材质表现干净，轮廓明确，色彩柔和但富有夜景霓虹的层次感。
>
> 场景主体是一处日式便利店街角……（元素穷举清单）
>
> 不要人物，但便利店内部一定要有足够内容，并且可以透过大面积玻璃窗清楚看到店内……（室内清单 + 冷暖对比）
>
> 加入持续降雨、屋檐滴水、地面积水波纹、招牌灯箱轻微闪烁、自动门偶尔开合、雨水沿玻璃滑落、地面积水反射灯光、远处交通信号灯微弱变化。
>
> 负面：不要人物、不要 UI 元素、不要文字招牌、不要真实照片质感、不要景深模糊、不要悬浮脱离底座。

注意最后一段——**「不要人物」和「不要 UI」是用户原始需求里明确要的，写进负面清单能防止生成方自作主张加人。**

## 用于定时任务与自用指令

给定时任务/子任务写指令时，同一套骨架成立，但「风格」段换成「执行契约」：

| 段 | 定时任务里的对应 |
|---|---|
| 主体 | 要做什么 |
| 视角 | 输入从哪来、覆盖哪些文件/页面 |
| 风格 | 执行方式（先读后写、最小改动） |
| 约束 | 权限边界、不许做的事 |
| 负面清单 | 明确禁止项 |

**自用指令必须自足**——对方看不到你和用户的对话上下文。缺了「覆盖哪些文件」就会漏做，缺了「不许删改用户已有内容」就会误伤。
