# 分域补充维度

六段骨架是通用底座。不同产物类型还有各自的专属维度，缺了会明显掉质量。

## 图像生成（image_generate / 外部 T2I）

**额外必写：**

- **画幅比例**：与工具的 aspect_ratio 对齐，否则构图被裁
- **光线方向与时间**：正面光/侧逆光/顶光；白天/黄昏/夜景
- **景深处理**：微缩场景通常要「全景深、不开浅景深」
- **色彩数量上限**：3-5 色主调 + 强调色，避免模型堆杂色

**写实 vs 插画的判定**：想要插画风必须显式写，并给可验收特征（见 SKILL.md「风格描述」）。

**常见失败**：

| 现象 | 原因 | 修法 |
|---|---|---|
| 每次生成风格不一致 | 风格词太抽象 | 换成可判定的视觉特征 |
| 元素漏了 | 清单不够穷举 | 补充同类项，给数量 |
| 加了不要的人物 | 负面清单没写 | 显式写「不要人物」 |
| 尺寸/比例错 | 没写死 | 给明确数字 |

## 视频生成（图生视频 / T2V）

在图像维度之上额外需要：

- **运动主体**：谁在动、动什么
- **运动幅度**：轻微/中等/剧烈
- **时长与节奏**：短镜头通常 2-5 秒最稳
- **镜头运动**：固定/推拉/摇移/环绕
- **首尾帧一致性**：需要时指定起止状态

**常见失败**：

- 主体变形 → 运动幅度写「轻微」并降低时长
- 画面闪烁抖动 → 强调「稳定镜头、无抖动」
- 内容突变 → 指定单一连续动作，不要多个动作叠加

## 3D 建模（bpy / Blender / glTF 导出）

这类 prompt 额外需要：

- **精度档位**：块面级 / 高精细 / 角色级。**必写**，否则默认出概念图
- **建模方式**：程序化几何 / 多分辨率雕刻 / 手工建模
- **可交互性**：是否需要拖拽旋转缩放、是否要可导出
- **交付格式**：.blend / .glb / .stl
- **比例基准**：真实尺度 vs 微缩展示

### 实测：只写材质名 / 灯光形容词 = 白写（2026-10-04 实测）

用本 skill 的六段骨架扩写「做个雨夜便利店」，产出 183 网格。**但三次返工全因 prompt 写得不够具体：**

| prompt 原文 | 实际后果 | 必须改成 |
|---|---|---|
| 「大面积玻璃橱窗」 | 实心 cube，室内全黑 | `半透明玻璃，alpha=0.28，Transparent+Emission 混合` |
| 「店内灯光明亮温暖」 | 灯打在窗外，照不进去 | `店内点光源 (0,1.4,2.6) energy=260 size=2.0 色温 (1.0,0.82,0.55)` |
| 「店内陈设…可透过玻璃看到」 | 实心墙体把货架全包住 | `墙体三面围合，正面留空开口` |
| 「使用 EEVEE」 | Blender 4.5 报枚举错误 | `BLENDER_EEVEE_NEXT`（4.2+ 改名，4.1- 用 `BLENDER_EEVEE`） |

**规律：形容词（「明亮」「温暖」「半透明」「玻璃」）必须落成可执行的数值/枚举/结构。** 写作者以为描述清楚了，执行者只能猜，猜错就是返工。

### 灯光要写四要素

`位置 + 类型 + 强度 + 色温`。缺一项就会跑偏。**室内照明必须用 POINT 而非 AREA**——面光源贴在窗口只会照亮外墙，货架仍然是黑的。

### 常见失败

| 现象 | 原因 | 修法 |
|---|---|---|
| 出概念图不像成品 | 没写精度档位 | 显式写「高精细建模」 |
| 渲染耗时过长 | 没限定 | 写清渲染尺寸与帧数 |
| 导出后材质塌陷 | 未提材质规范 | 写清材质类型（卡通/Principled/PBR） |
| 室内一片黑 | 玻璃实心 / 灯在墙外 | 半透明材质参数 + 店内点光源 |
| 室内陈设看不见 | 墙体是实心 cube | 写明「三面围合，正面开口」 |

## 验证方法：像素探针优于目视描述

渲染完**不要只凭 VLM 的自然语言描述判断成败**——它会漏报也会误报。实测：VLM 两次说「招牌看不出发光」，而像素实测该处 R-B=+40.5、亮度 210，发光成立。

**用像素差值做客观判据：**

```python
# 冷暖对比：R-B 为正=暖，为负=冷
def probe(im, x, y, r=14):
    px = [im.getpixel((x+dx, y+dy)) for dx in range(-r,r,2) for dy in range(-r,r,2)]
    return sum(p[0] for p in px)/len(px) - sum(p[2] for p in px)/len(px)
```

**关键前提：先算出物体在画面中的真实坐标，别靠猜。** 用
`bpy_extras.object_utils.world_to_camera_view(scene, cam, obj.matrix_world.translation)`
把物体名投影成屏幕坐标。实测中我一度探错了区域，得出「改灯无效」的错误结论——加了两轮灯都不动，其实光打对了，是探针在错的位置量空气。

## 代码生成

- **目标平台与版本**：如 React 18 + Vite
- **范围边界**：只做哪些、明确不改哪些
- **验收标准**：可执行的检查命令或可观察现象
- **禁止项**：不要引入新依赖、不要改无关模块

**代码 prompt 最忌讳模糊验收**。「优化性能」不可验收，「Lighthouse LCP 从 4.2s 降到 2.5s 以下」可验收。

## 搜索与研究

- **实体/时间/地区**：把口语问题拆成可检索的关键字
- **来源偏好**：官方文档 > 论坛 > 博客
- **时效性**：是否限定近期
- **要什么粒度**：只要结论 / 要数据 / 要原文引用

**关键**：不要直接把用户原句丢给搜索——先抽实体。中文口语里的「那个框架」对搜索引擎是零信息。

## 角色 / 人设

- **身份与背景**
- **性格与语气**
- **外形特征**（可画的）
- **禁止项**：年龄、画风、表情等容易跑偏的维度要显式约束
