# 玩法机制分析协议

## 目标

提炼“系统如何运作”，而不是复制剧情、数值表或完整内容。输出应能让团队重新实现类似机制，但不直接复用目标数据。

## 观察维度

### 核心循环

```text
行动 → 消耗 → 反馈 → 收益 → 成长/解锁 → 新行动
```

记录每轮时长、玩家决策点、失败代价和反馈延迟。

### 经济与资源

- 资源类型、来源、消耗和上限
- 商店价格、通胀、兑换率和稀缺性
- 随机奖励、保底、权重和重复惩罚
- 资源转换链和套利空间

### 战斗与能力

- 行动顺序、行动点、冷却和状态叠加
- 伤害/治疗公式、暴击、闪避、抗性和护盾
- 增益、减益、触发器和持续效果
- 数值成长、等级压制和边际收益

### 解锁与进度

- 解锁顺序、门槛、捷径和回溯
- 每日/每周节奏和长线成长
- 失败恢复、重试成本和沉没成本设计

## 事实与推断

所有机制结论分成两类：

```text
Observed:
- 直接观察到的行为或未加密配置

Inferred:
- 根据多个观察推导出的公式或规则

Unknown:
- 需要更多样本或授权数据
```

不要把推断写成确定事实。

## 最小验证实验

每个机制至少设计一个可重复实验：

1. 固定初始状态。
2. 只改变一个变量。
3. 记录输入、输出、耗时和异常。
4. 重复至少两次。
5. 结果用表格或公式表示。

## 输出

- 机制循环图
- 资源和行动表
- 公式/概率模型
- 玩家决策点
- 设计风险和可替代实现建议
