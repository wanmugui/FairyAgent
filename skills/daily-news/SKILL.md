# Daily News Skill

## 触发

仅在用户**明确要"今天的新闻/今日要闻"**时使用。即便是"国内新闻"或"国际新闻"，如果用户没说要"今天/最新/最近"，先询问时间范围，不要默认跑这一套（它会打 8 个源，耗时长）。

## 用户可见输出守则

- **禁止**告诉用户"正在抓取人民日报/新华网/微博/百度"等内部抓取细节；用"正在整理今日要闻"等自然表达。
- 最终回复里把生成的简报**直接呈现给用户**（按 [国内]/[国际]/[财经] 三段），并在结尾附上文件路径，让用户知道已落盘。
- 文件路径用 `Markdown` 链接，例如 `[今日要闻](workspace/output/daily_news_2026-09-01.md)`。如果用户想要更详细的某条新闻，用 `web_fetch` 跟进。

## 执行流程

1. 用 `bash` 跑 `python <workspace>/skills/daily-news/scripts/daily_news.py`。脚本会写一份 `workspace/output/daily_news_<YYYY-MM-DD>.md`，并把路径打到 stdout。
2. 用 `read_file` 读这个文件（它就是已经格式化好的简报），把它直接回复给用户。
3. 用户如果想"再深入看某条"，用 `web_fetch` 拉对应 URL。
4. 用户如果问"昨天/前天"的新闻，不要重跑 skill——直接说"本 skill 只生成当天简报，更早的需要用 `web_search`（带日期 query）"。

## 失败模式

- 脚本会写一份 Markdown 即使所有源都失败（标题写"暂无"）。这是兜底，不是 bug。
- 任何源 fetch 失败都会被脚本忽略，不影响其他源。
- 网络完全不通时脚本会写空简报并 print 路径——告诉用户"今日要闻源暂时不可达"。

## 不要做

- 不要试图把简报**直接 push 到 QQ / 微信 / 邮件**——本 skill 不做推送。生成文件就够了。
- 不要把日报里出现的**娱乐/明星**关键词作为工作项去 follow；它们已经被脚本过滤了。
- 不要在用户**没要**的情况下每天自动跑——fairy agent 不带定时器，调用必须由对话触发。
